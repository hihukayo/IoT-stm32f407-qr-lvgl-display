> 本文如实列出**没有做**和**没有验证**的部分，避免任何"虚假支持"声明。

## 1. 未实现的功能

| 项目 | 状态 | 说明 |
|:--|:--|:--|
| **Data Matrix（第二种码制）** | ❌ 未实现 | 协议保留 `symbology=0x02`；固件返回 `UNSUPPORTED(7)`，上位机下拉框显示"暂未支持"且无法提交。架构上 `qr_service.c` 已按 `qr_symbology_t` 分派、`bmp_stream`/协议/界面与码制解耦，后续可加独立模块。**未实现就是未实现，不影响必做项验收（AC-011 不适用）。** |

| **触摸 / 按键交互** | ❌ 未实现 | 屏幕只做显示。板载按键（PA0/WK_UP）本版本未使用。 |
| **USB CDC 虚拟串口** | ❌ 未实现 | 板载 Micro USB 是 USB Device（PA11/PA12），未移植 USB 协议栈；串口走外部 USB-TTL。 |

## 2. 中文二维码的跨扫码器一致性（重要风险）

**现状**：文本按 UTF-8 原始字节送入 qrcodegen byte 模式，**不写 ECI(26)**。扫码器此时会按
"默认字符集"解释字节流：

| 解码器 | 实测结果 |
|:--|:--|
| OpenCV `QRCodeDetector`（本项目已实测） | ✅ `二维码测试-中文 UTF-8` 逐字节正确 |
| 手机微信 / 支付宝 / 系统相机 | ⬜ **未实测**，不保证 |

原因：多数现代扫码器默认按 UTF-8 解释，但部分老实现会按 ISO-8859-1/GBK 处理，从而乱码。
**这不影响 ASCII 文本与 URL**（QR 规范里 ASCII 无需 ECI）。

如果要彻底解决，需要支持 ECI 的编码库（qrcodegen 不直接支持，需要在生成 segments 时插入
ECI 段）。这属于后续工作，本文档不做承诺。

> 上板测试时请按 `docs/04-test-record.md` 的 **T-109** 用两种不同扫码软件记录实际输出，
> 并把结果回填到测试记录，**不要**直接写"通过"。

## 3. 硬件相关的不确定性（必须按实屏确认）

| 项目 | 默认值 | 不确定性 |
|:--|:--|:--|
| 颜色顺序（BGR/RGB） | `BOARD_LCD_MADCTL_BGR = 1` | 不同模块可能相反 → 红蓝互换 |
| 是否反色（INVON） | `BOARD_LCD_INVERT_COLOR = 1` | 部分模块需要关掉 |
| 行列偏移 | `0 / 0` | 240×320 的 ST7789 通常为 0，个别模块为 80 |
| 背光有效电平 | 高有效 | 少数模块低有效 → `BOARD_LCD_BL_ACTIVE_HIGH = 0` |
| 屏幕 RESET | **无**（J4 第 6 脚是 SDO） | 模块若无 RST 靠上电复位 + 软件复位；有 RST 需飞线并改宏 |
| SPI 速率 | 10.5 MHz | 排线长/模块差可能花屏，降到 5.25 MHz |
| 串口电平 | 3.3 V TTL | 核心板无 USB 转串口，必须外接 USB-TTL |

以上都是"上板后改一个宏"的事情，代码里已集中到 `board_config.h`，不会散落在业务逻辑中。

## 4. 功能边界

| 限制 | 说明 |
|:--|:--|
| 文本长度 | 1–256 字节（UTF-8 计），超出返回 `TOO_LONG`，**不静默截断** |
| payload 上限 | 512 字节（协议层硬限制） |
| QR 版本 | 1–20（v20 = 97×97 模块）。版本 40 也可编码但需要更大缓冲，本版本未开放 |
| 单帧最大字节 | 9 + 512 = 521 |
| 图片分块 | 每块 ≤ 448 字节数据（payload 452），共 18 块 |
| 图片传输总时长 | 7742 B + 帧开销 ≈ 8.4 KB，115200 下约 0.8 s |
| 同时连接数 | 1 个串口 |
| 屏幕内容 | 一张二维码 + 顶部标题/信息 + 底部状态 |

## 5. 协议层的取舍

| 取舍 | 原因 |
|:--|:--|
| 不支持帧重传/窗口 | 115200 下 8 KB 传输已足够快，简化固件状态机 |
| `SET_QR` 默认不自动重试 | 避免重复执行副作用（需求 7.2 也建议 MVP 不重试） |
| 坏帧只丢弃、不回 `CRC_ERR` | 帧本身不可信，回包反而可能被误解；上位机靠 ACK 超时感知 |
| 图片流期间返回 BUSY 而非中止 | 按需求 5.7 的推荐做法，避免半张图 |
